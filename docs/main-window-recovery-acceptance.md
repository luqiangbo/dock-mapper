# 主窗口黑屏排查与异常恢复

## 当前证据

- 2026-10-18 用户再次启动开发模式后复现。通过 Windows 窗口捕获看到整块深灰，通过真实 WebView DevTools 确认 document 已加载完毕但 `#root.childElementCount` 为 0。
- Console 没有异常；旧 HTML 加载的分块包含 `…3d9d47`，当前入口等待的 `…4728f1` 和 `…f2895d` 未注册。入口及错误边界根本没有执行，不能通过 React 异常捕获定位。
- 在同一真实窗口补载缺失分块后，root 从 0 恢复为 1，菜单和仪表盘恢复。后续窗口捕获及 UI Automation 均看到了仪表盘和侧栏。
- 开发 HTML 响应原本没有 Cache-Control，存在跨编译版本混用的条件。另发现构建切换调用原生 relaunch：进程父子关系和日志确认发生了原生重启，开发服务随后停止。开发模式不能沿用正式包的自行重启流程。

## 已增加的恢复与诊断

- 主窗口最外层增加错误边界，覆盖设置初始化、主题和应用组件的 React 渲染错误。
- 出错时显示不透明背景的 antd 错误提示，包含重试显示和重新加载界面入口。
- 渲染错误、未捕获脚本异常和未处理 Promise 拒绝写入既有 application 运行日志。窗口重新挂载会清理旧监听。
- 重试不清空配置或历史；重新加载可能丢失尚未保存的内存状态。
- 开发服务器统一发送 `Cache-Control: no-store`，JavaScript 使用内容哈希文件名，避免同一地址对应不同版本入口。
- 构建切换在开发模式显示退出旧实例并重新执行 `pnpm tauri dev` 的提示，不自动退出被 CLI 监视的原生进程；正式包保留原生重启。需要重启时先不清理前端偏好，避免旧原生状态与新前端偏好混用。
- 独立静态启动脚本不依赖 React、分块运行时或 antd。React 12 秒未挂载时写入现有 application 日志，并仅自动尝试一次带查询参数的加载；仍失败显示可重试错误页。挂载成功清理查询参数。这个异常回退使用浏览器原生元素，因为 antd 本身属于未启动的入口。
- 不修改系统显示设置；原生 WebView/GPU 绘制故障仍不受 React 错误边界保护。

## 验证范围与最短人工路径

- 补充错误页无需主题上下文即可显示、日志记录和监听清理，以及开发模式不 relaunch、启动超时单次恢复和正常挂载不重载的前端测试，按仓库约束不运行前端测试套件。
- 已真实观察黑屏、通过 DevTools 恢复同一窗口、检查恢复后的仪表盘画面。修改后开发响应实测为 no-store 和带哈希入口；配置重载后应用进程 PID 未变化，初始化错误已写入日志并显示明确提示。
- 启动脚本超时后的自动恢复和错误页、正式安装包重启、反复冷启动尚未做真实交互验证；不能把单次恢复视为所有黑屏情况都已排除。
- 主窗口正常打开后切换页面；若再次黑屏，记录出现时间、标题栏/菜单是否可见及能否操作。若出现错误页，先记录错误文字再重试；保留对应 application 日志用于下一轮定位。
- 截图取色后检查“最近”色卡：色块与收藏按钮分开、边框清晰；点击色块复制，点击星标收藏，再次打开确认收藏保留；失败提示仍沿用现有通知。
