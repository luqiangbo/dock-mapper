# 阈值提醒、OCR 重试和采样诊断验收

> 历史交付记录：仪表盘、阈值提醒与温度／GPU 功能已调整，当前行为以 [精简仪表盘与本机运行日志验收](runtime-log-dashboard-acceptance.md) 为准。原采样脚本已移除，本文旧命令不适用于当前版本。

## 实现入口与状态

- 挂件设置 → 阈值提醒：CPU、内存、电池默认关闭，首次开启分别采用 80%、85%、20%。阈值为 1–100 的整数，复用挂件自动保存和失败重试。只有保存成功的规则参与判断。
- 连续三次采样越界才生成提醒；CPU／内存采用 ≥，电池采用 ≤，同类冷却十分钟。正常或缺失数据、规则变化，以及超过十五秒的采样中断均重新累计。
- 主窗口显示时使用应用内通知；隐藏到托盘后按现有约十秒接收频率继续判断和记录，恢复后显示未读列表，不补弹旧通知。不是后台每秒判断，也不提供 Windows 系统通知。
- 仪表盘 → 阈值提醒：首次为空、读取错误、写入错误及重试分别呈现。最多五十条，支持单条／全部标为已读。记录和已读状态沿用本机 localStorage；写入失败保留内存记录，进程退出前仍需重试成功才能持久化。读取失败时暂停判断，避免覆盖无法读取的旧记录。
- OCR 面板 → 重试：初始化失败后再次识别，间隔达到两秒会重新初始化；冷却期间反馈剩余等待时间。预热不重试失败引擎，普通识别失败复用已有引擎；成功引擎闲置十分钟后释放。捕获代次和取消校验覆盖初始化前后及识别结果。
- 按键映射：首次加载期间禁用依赖数据的操作；读取失败显示页内错误和重试，正常空规则显示“暂无映射规则”。草稿保存成功但状态刷新失败时保留草稿，提供“刷新状态”，系统应用／恢复暂时禁用。
- 全局设置 → 导出诊断：新增采样统计，包含系统循环及 GPU／温度查询的次数、累计／平均／最近／最大耗时，以及进程启动、有效数据、无数据、失败和超时次数。统计在内存中，随进程重启重置，测量时间自统计初始化起计算。
- 系统循环计时不含等待，GPU／温度异步查询另计完整耗时，三者不能直接相加作为整个应用耗时。

## 短时查询基线

原始结果见 [sampling-baseline.json](sampling-baseline.json)。本机 Windows 11，2026-10-14（Asia/Singapore）采集，总时长 60.09 秒。三个场景各开放二十秒启动窗口，GPU 有数据时每两秒、温度每五秒，否则三十秒重试；同类查询不重叠，单次超时五秒。

| 场景 | 来源 | 启动次数 | 有效／无数据／失败／超时 | 平均耗时 | 最大耗时 |
| --- | --- | ---: | --- | ---: | ---: |
| GPU 单独 | GPU | 1 | 0／0／1／0 | 3158.052 ms | 3158.052 ms |
| 温度单独 | CPU 温度 | 1 | 0／1／0／0 | 363.137 ms | 363.137 ms |
| 同时启用 | GPU | 10 | 10／0／0／0 | 828.582 ms | 1305.696 ms |
| 同时启用 | CPU 温度 | 1 | 0／1／0／0 | 329.068 ms | 329.068 ms |

测量复用当前查询脚本和 Windows PowerShell 启动参数，不调用旧应用程序。墙钟时间包含至多约 25 ms 的脚本轮询延迟。独立调度不包含主循环 1–5 秒节拍造成的查询间隔量化，也不测整个应用 CPU、内存或电量。GPU 首次失败、后续成功表明存在启动阶段或提供者差异，当前样本不足以确定原因；温度无数据不等同于查询失败。本轮没有替换采样后端，没有可报告的前后提速比例。

复现命令（PowerShell 7，使用已经安装的工具）：

```powershell
pwsh -NoProfile -File scripts/measure-sampling.ps1 -OutputPath sampling-baseline.json
```

## 验证与最短人工路径

- 前端新增行为测试覆盖提醒触发／冷却、规则变化与旧读取隔离、后台记录、已读重开、容量上限、读写失败重试，以及映射首次失败恢复、离页与过期读取、保存成功后刷新失败。遵循仓库验证边界，本轮不执行 Vitest，交由现有 CI 执行。
- Rust 新增测试通过假引擎验证初始化失败后恢复、冷却、预热不重试、引擎复用及取消结果隔离；统计测试覆盖耗时、分类和进程重启清零，不初始化 OCR 模型。
- 交付检查为根目录 `pnpm typecheck`，以及 `src-tauri` 目录 `cargo test -- --skip model`；没有运行全量构建、格式检查或模型测试。
- Rust 核心回归已执行：152 项通过、0 失败，3 项模型相关测试被过滤；测试执行耗时 0.42 秒，首次增量编译耗时约三分半。
- 静态检查 `pnpm typecheck` 已通过；类型检查包含新增测试文件，但不代表前端行为测试已执行。
- 未做真实 Tauri 窗口交互验证。旧 debug／release 程序不包含本次改动，不能用于新功能验收。

人工验收：挂件设置开启低 CPU 阈值 → 等保存成功 → 等三次采样 → 仪表盘查看提醒 → 隐藏到托盘后等待 → 恢复查看未读 → 单条／全部标已读 → 重启检查保留。另检查无电池及正常温度源缺失、规则保存失败、提醒存储读写失败的反馈与重试。

OCR：在可控测试环境注入初始化失败 → 面板显示错误 → 两秒内重试检查冷却提示 → 恢复初始化条件后重试 → 确认识别可恢复；加载期间取消或开始新截图，旧结果不得落入新会话。不要通过改动真实模型文件制造错误。

映射：注入首次读取失败 → 确认页内错误且操作禁用 → 重试恢复；注入保存成功后的状态读取失败 → 草稿保留 → 点击刷新状态 → 应用／恢复重新可用。此流程无需写入系统注册表验证读取反馈。
