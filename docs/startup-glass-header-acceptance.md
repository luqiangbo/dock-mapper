# 连续启动反馈与毛玻璃顶栏验收

## 行为与边界

- 主窗口 HTML 自带 DockMapper 名称、“正在启动…”及不定进度的原生 progress。首帧样式、主题脚本和资源看门狗均独立于入口分块，React 尚未执行时也有可见提示。
- 首帧只读取已有主题偏好，不写设置；读取失败跟随系统主题。React 接管后使用同一布局和背景，进度区域改用 antd Spin，提示“正在初始化应用…”。初始化超过 8 秒只补充等待说明，不标记失败、不重复执行初始化，也没有最短展示时长。
- 初始化失败显示具体原因和重试。保留原有两阶段配置握手及共享初始化 Promise，依赖配置的窗口仍在正确时机启动。旧观察者在卸载或重试后失效，迟到结果不能覆盖新界面。
- React 挂载只解除资源看门狗，不代表整个应用就绪。原有 12 秒资源检测、最多一次自动重载、最终错误及手动重试保留。首次页面仍由已有 DeferredPage 展示加载反馈，已访问页面不新增整页加载。
- 右侧顶栏高 56 px，以绝对定位覆盖主内容区；内容初始留出 72 px，滚动时从顶栏下经过。复用主题中浅色 78%、深色 82% 的玻璃底色，加 16 px 模糊；高对比度或不支持模糊时使用实色。
- 主内容仍使用原滚动容器和页面位置记录。滚动条稳定保留 7 px 通道，顶栏避开该通道；焦点被顶栏挡住时即时避让，弹层中的焦点不推动底层页面。标题拖拽、主题及窗口按钮和左侧导航保持原流程。
- 不新增依赖、IPC、持久化设置或原生窗口隐藏流程。本轮没有修改设置重置顺序，也没有运行生产构建。

## 最短人工路径（未执行）

1. 正常启动及调试环境延迟入口分块，确认窗口有“正在启动…”，随后接到“正在初始化应用…”，没有空白、闪白或位置跳动；快速启动没有被人为拖慢。
2. 延迟初始化超过 8 秒，确认只增加等待文字，仍保持同一个初始化任务；让响应成功后立即进入页面。模拟初始化失败，确认具体错误、重试和再次进入正常。
3. 阻止入口资源执行，确认最多自动重载一次，然后显示错误和手动重试；React 已挂载但初始化较慢时不能触发资源重载。
4. 在较长设置页上下滚动，确认内容经过毛玻璃下方，标题固定、首行初始未被遮挡；滚动条顶端可直接抓住拖动。
5. 切换明暗主题、高对比度，调整窄窗口及不同 DPI；检查标题拖拽、最大化/还原、最小化、关闭、菜单和弹窗层级。用 Tab 聚焦靠近顶栏的输入框，确认完整可见且弹层焦点不会带动页面。
6. 设置页修改输入并滚动，切换其他已访问页再返回，确认输入及滚动位置保留，不出现新的整页加载。
