# 截图启动与选区对比验收

## 可观察行为

- 历史页、截图设置页的“开始截图”立即进入加载状态，直到浮层已显示或启动失败。
- 主窗口先注册启动状态监听，再请求命令；提前到达的成功/失败不会被命令响应覆盖。
- 按钮、全局快捷键、托盘共用后端启动状态。重复请求明确提示“截图正在启动”。
- 原生捕获、浮层就绪、底图读取/解码/绘制、窗口显示失败会在主窗口反馈；失败通知提供“重试截图”。
- 请求被接受后，8 秒内没有显示则失败，释放启动状态、恢复按键展示。迟到任务不能显示旧浮层或覆盖新代次。
- 浮层先完成事件监听注册，再报告就绪；就绪状态按窗口记录。失败浮层关闭后可重新创建。
- 标注编辑器独立懒加载，加载失败显示重试入口；基础框选、原图输出不依赖编辑器模块成功加载。
- 选区外部使用 55% 黑色遮罩，选区重绘原始截图，不使用亮度或对比度滤镜；保留黑白双层边界。
- 遮罩只存在于背景交互画布，复制、保存、贴图继续使用单独的原图/标注导出通道。
- 启动状态和遮罩均不持久化，没有新增设置项或依赖；图片保留现有二进制通道。

## 自动化覆盖与边界

- `captureStartup.test.ts`：监听顺序、实际显示前持续加载、提前终态事件、重复点击、失败重试和旧事件隔离。
- `useCaptureBootstrap.test.ts`：监听注册失败、底图读取/解码/显示失败上报、绘制后显示、旧解码迟到隔离。
- `captureBackground.test.ts`：原图选区、55% 外部遮罩、重置裁切及混合状态、边缘选区及 1/1.25/1.5/2 倍缩放坐标。
- Rust `screenshot::startup::tests`：成功/失败状态、各启动边界失败后重试、重复启动和旧代次隔离；IPC 测试限制错误上报权限仅对截图浮层开放。
- 按仓库约束，本地只执行 `pnpm typecheck`、`cargo test -- --skip model`；前端测试已编写，未运行前端测试套件。
- 纯状态测试不等同于原生截图、真实计时器调度、WebView 解码或屏幕像素效果的端到端验证。

## 最短人工路径（未做真实交互验证）

1. 在截图历史及截图设置分别点击“开始截图”，确认按钮先加载、浮层出现后解除加载；连续截图、Esc 取消、再截图。
2. 用全局快捷键、托盘重复启动，确认共享启动状态；快速重复点击不会启动多个捕获任务。
3. 在调试器中让 `window.api.getFullScreenshot` 或图片加载拒绝，确认主窗口显示失败并可重试；阻止浮层报告绘制完成，确认约 8 秒后解除加载、恢复按键展示。放行旧请求后重新截图，确认旧浮层不出现。
4. 在明亮/深色画面以及 125%/150%/200% DPI、不同显示器上，依次测试窗口候选、拖动框选、边缘选区、调整及编辑阶段，确认选区维持原亮度、外部明显压暗、黑白边界可见。
5. 分别复制、保存、贴图，确认成品无黑色遮罩和选区边界；模拟标注模块加载失败，确认仍可框选并输出原图，且有编辑器重试提示。

当前没有真实操作 Tauri 窗口，以上交互与视觉效果均需人工确认。
